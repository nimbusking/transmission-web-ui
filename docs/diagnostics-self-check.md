# 2.1.0 用户故障自查与检测记录检查表

本表供用户初步判断、尝试解决问题，并整理可供他人核实的故障记录。配合[诊断与重放说明](diagnostics.md)使用；不要求安装开发工具，也不要求完成所有项目。无法判断的项目填“未知”，未执行的项目填“未执行”。

本表作为仓库公开文档维护，不加入生产页面或发行包。生产页面提供本地日志采集和导出；离线重放工具需要另外取得对应源码、依赖或开发构建。公开文档不意味着需要公开自己的日志或部署信息。

## 一、先保留现场

- [ ] 记下故障发生时间及所在时区，例如 `2026-11-17 14:32:10 +08:00`，并记录当时的操作、预期结果和实际结果。
- [ ] 在登录页或“关于”展开“诊断信息 / Diagnostics”，先“导出当前日志 / Export”。有对应历史日志时一并导出，保留原始 JSON。
- [ ] 记录面板显示的存储模式、摘要时间范围、条数、已淘汰条数。确认时间范围覆盖故障，不能只凭“导出成功”判断已经记录到故障。
- [ ] 若问题涉及界面显示，另存截图并记下窗口大小、缩放比例、语言和主题；截取前遮盖任务名称、路径等私人信息。
- [ ] 导出完成前不清除站点数据或日志，不反复刷新。内存模式刷新后可能丢失记录；持久日志也有期限和容量淘汰。

若页面空白：等待约 15 秒，查看是否出现独立的启动诊断导出入口；它依赖启动诊断脚本本身成功加载，并非必然出现。没有入口时，记录空白页截图及开发者工具中的资源加载失败状态。不要把“没有日志”解释为“没有故障”。

## 二、填写环境与复现条件

| 检查项 | 填写内容 | 如何取得或说明 |
| --- | --- | --- |
| 前端版本与构建 | 版本：____；buildId：____ | 导出包 `app.version`、`app.buildId`；没有包时填部署版本，未知就注明 |
| 服务端 | Transmission 版本：____；RPC 版本：____ | 关于信息、服务端版本信息或日志环境摘要；不要用前端版本代替 |
| 设备 | 操作系统及版本：____；桌面/手机/平板：____ | 记录实际发生问题的设备 |
| 浏览器 | 名称与完整版本：____ | 浏览器“关于”；同时记录隐私模式、扩展是否启用 |
| 访问方式 | HTTP/HTTPS：____；直连/反向代理：____；同源/跨域：____ | 只描述结构；公开反馈无需写真实域名、IP 或完整 URL |
| 规模与设置 | 任务数约：____；刷新间隔：____；语言/主题：____ | 大列表或特定显示设置可能影响结果 |
| 现场状态 | 已连接/登录失败/空白页：____；其他标签页：____ | 多标签操作、其他客户端修改也可能影响状态 |
| 发生频率 | 每次/偶发：____；复现次数/尝试次数：____ | 例如 2/5；未尝试不要写“无法复现” |
| 最近变化 | 升级、代理配置、浏览器更新等：____ | 变化与故障时间接近仅是线索，尚不能证明因果 |

## 三、按症状自查

先导出，再逐项尝试；每次只改变一个条件，并在第五节记录结果。不要为排障删除真实下载、批量修改任务或关闭服务端鉴权。

| 现象 | 检查与可尝试的处理 | 应保留的证据及判断边界 |
| --- | --- | --- |
| 空白页、升级后无法启动 | 查看脚本请求是否 404、返回 HTML 或被拦截；确认部署的 HTML 和 assets 来自同一构建。保留现场后尝试强制刷新；部署者检查资源路径和代理缓存 | 资源相对路径、状态码、启动包；缺资源可指向部署问题，单凭空白不能认定浏览器不兼容 |
| 登录失败、401/403 | 检查输入与 RPC 地址配置；区分代理认证和 Transmission 认证，交由部署者核对对应配置 | 状态码、发生阶段；不要粘贴密码、Cookie、Authorization 或完整请求头。403 的来源需进一步核实 |
| 出现 HTTP 409 | 观察后续是否自动重试成功；持续失败时请部署者检查 RPC 路由和会话头传递 | 首次 409 可属于正常会话协商；只有持续失败才作为故障记录，不提交会话头的实际值 |
| 网络错误、502/504、超时 | 确认服务是否运行、代理是否可达；查看浏览器是否报告证书、混合内容或跨域拦截，按具体错误修正配置 | 错误类别、时间、状态码及脱敏后的浏览器提示；“网络错误”本身不能确定是前端还是服务端原因 |
| 开始/暂停超时，但任务状态后来改变 | 等待连接恢复后刷新查询，核对实际任务状态，再决定是否重试 | 记录操作结果和后续查询结果；超时不代表服务端未执行，不要连续重复写操作 |
| 列表旧状态、部分任务操作失败 | 等当前操作结束后手动刷新；查看是否仍显示旧数据或部分失败，必要时重连；记录其他客户端是否正在修改 | 哪些操作成功/失败、刷新前后状态、是否自动恢复；用匿名编号对应任务，不提交真实名称 |
| 仅某个浏览器显示异常 | 保留原环境后，用另一浏览器或无扩展的新配置进行同样步骤对照；比较缩放、窗口、语言和主题 | 两组条件及截图。对照环境不再出现只能缩小范围，不能直接证明原浏览器存在缺陷 |
| 显示内存模式、历史日志消失 | 检查站点存储限制、隐私模式、是否清过站点数据；在普通浏览器配置中再试，并及时导出 | 记录模式及是否刷新过；IndexedDB 不可用会降级，历史过期或淘汰也会导致记录缺失 |
| 操作卡顿或大列表异常 | 记录任务数量、持续时间和刷新间隔；在相同条件下分别观察采集开/关表现，先保存已有日志 | 单次体感不足以判定日志导致卡顿；附可重复步骤和观察，不必运行开发性能测试 |

需要查看开发者工具时，只摘录必要的错误类别、状态码及资源相对路径。网络面板原始响应、HAR、控制台文本和截图不经过本应用的脱敏处理，不能直接视为可公开附件。

## 四、记录一次可分析的复现

### 普通诊断：所有用户优先执行

- [ ] 确认“本地采集 / Local recording”已开启；关闭期间的故障不能事后补录。
- [ ] 执行能说明问题的最短步骤，记录时间与结果。高影响操作不为了日志重复执行。
- [ ] 导出当前日志及相关历史片段，核对日志时间与故障时间对应。包内 `at` 为 UTC，注意与本地时间换算。
- [ ] 文件存入自己选定的目录，例如 `故障记录/2026-11-17/`；保留原文件名，单独写说明，不改原包内容。

日志自动存放在当前浏览器、当前站点的 IndexedDB `transmission-web-ui-diagnostics`，不是 NAS 下载目录中的文件。不同浏览器或不同站点地址（协议、主机、端口变化）不能直接共用这份存储。手动导出位置由浏览器下载设置决定。

普通日志保留 30 分钟窗口，最多 1000 条或 2MiB；持久普通包 24 小时过期，故障片段和增强包 7 天过期，还可能提前因容量淘汰。详细存储结构及清理规则见[保存在哪里](diagnostics.md#保存在哪里)。

### 增强录制：问题适合时执行

适用范围为列表刷新、概览选择/读取、批量开始/暂停、重连及状态协调。视觉排版、浏览器进程崩溃、原始文件名相关问题及服务端内部执行不保证由重放还原。

- [ ] 使用 HTTPS 或 localhost；普通 HTTP 局域网站点仍可用普通诊断，但不满足增强录制所需 WebCrypto 条件。
- [ ] 已连接，等待现有批量操作或目录匹配完成；避免其他标签页修改设置。
- [ ] 点击“开始增强录制 / Record”，确认显示正在录制后，再执行最短复现步骤。录制不能追回开始之前的故障。
- [ ] 等待操作及请求完成，再点击“停止并保存录制 / Stop”。若始终无法完成，不无限等待；保留普通日志及不可重放包，并描述卡住的状态。
- [ ] 点击对应“导出录制”，保存增强包。它与“导出当前日志”不是同一个按钮。
- [ ] 记录 `capture.eligibility`、`capture.complete`、`capture.reasons`，不要自行修改资格、buildId 或完整性摘要。

| 资格或原因 | 含义与下一步 |
| --- | --- |
| `diagnostic-only` | 普通摘要，可辅助排障，不用于完整业务重放 |
| `replayable` | 具备进入验证的条件，尚不等于已成功复现；仍需对应构建进行离线验证 |
| `pending-work` | 停止时有未结束工作；如可安全复现，重新录制并等工作结束 |
| `duration-limit` / `capacity-limit` | 到达时间或总容量上限；缩短步骤、减少无关操作后重录 |
| `checkpoint-oversize` / `event-oversize` / `final-state-oversize` | 检查点、单事件或最终状态过大；保留诊断包反馈，单纯缩短录制不一定解决。不要删除真实任务来规避限制 |
| `unsupported-action` / `unsupported-detail` / `unsupported-method` | 超出支持范围；可仅录制范围内步骤，否则用普通日志和文字描述 |
| `settings-change` / `external-change` | 设置或外部变化打断录制条件；固定设置、避免其他标签页修改后重录 |
| `recording-disabled` / `cleared` | 录制中关闭采集或清除日志；恢复采集后重新开始 |
| `integrity-unavailable` | 无法生成完整性摘要；核对安全访问环境，保留原包及原因 |
| `coverage-gap` / `schema-coverage-gap` / `missing-request` 或其他原因 | 数据覆盖或关联不满足要求；按原样反馈原因和步骤，不手工“修复”JSON |

增强录制最多 5 分钟、10000 个事件、10MiB，单事件上限 512KiB。`ineligible` 包仍可能帮助诊断；筛选界面列表不保证缩小底层全量检查点，因此不保证解决超限。

## 五、记录处理与复查结果

每执行一项处理填写一行。复查应使用相同操作和尽量相同的环境；偶发问题一次不再出现，记录为“暂未复现”。

| 时间（含时区） | 唯一改变的条件或处理 | 检查步骤 | 预期结果 | 实际结果、次数 | 对应附件 |
| --- | --- | --- | --- | --- | --- |
| ____ | 例如：强制刷新，其他条件不变 | ____ | ____ | ____ | ____ |
| ____ | ____ | ____ | ____ | ____ | ____ |

- [ ] 结果选择：已恢复且重复检查通过 / 暂未复现 / 仍可复现 / 无法继续检查。
- [ ] 若已恢复，记录有效处理和验证次数，保留最初故障包，避免只提交恢复后的空日志。
- [ ] 若仍存在，保留最短复现步骤和最接近发生时间的附件，再提交反馈。

## 六、有开发环境的用户：可选离线验证

按[开发者重放说明](diagnostics.md#开发者重放)执行，不需要、也不要把开发重放入口部署到实际实例。普通用户跳过本节即可反馈。

- [ ] 输入是完整增强包；取得与 `app.buildId` 对应的开发重放构建或归档。相同版本号不一定是相同构建。
- [ ] 记录命令、浏览器引擎、源/目标 buildId 和退出码；保留 `report.json`、`events.jsonl`，截图生成成功时也保留。
- [ ] `matched`：关键事件及状态断言匹配。说明录制的业务过程验证通过，不证明所有视觉、浏览器或服务端内部问题均被复现。
- [ ] `diverged`：记录首个差异及事件位置；它可能来自构建、环境或记录覆盖差异，不能直接认定为原始缺陷。
- [ ] `ineligible` 或命令启动失败：记录拒绝原因或终端错误；依赖/浏览器缺失与业务重放失败分别描述，不能记作“已复现”。
- [ ] 核对网络阻断与事件消费报告，不省略异常。不要修改包来绕过校验或添加真实 RPC 回退。
- [ ] 验证修复时使用 `--candidate --assert` 及独立的正确状态断言，分别保存修复前、修复后报告；不要以“旧错误仍出现”作为修复成功依据。

# 一体化安装器

## 登录入口整合（2.0.0-installer.5）

发布的单文件离线脚本已内嵌DSM登录入口配置和事务处理，无需再下载独立登录修复包。默认 `--login-page auto` 为启用认证、原端口9091的SynoCommunity 4.1.4-32配置系统nginx入口，RPC改为9093；保留原账号密码。现有独立入口自动识别并迁移到可切换的版本目录，升级时同时更新登录资源，避免旧副本长期滞留。

首次安装、已有入口升级均纳入同一个确认、备份和恢复事务。`--check`只检查配置和支持条件，不改端口或重载nginx；正式安装时检查新资源包含登录页，并验证匿名HTML可读、匿名RPC仍401且不带浏览器挑战头、认证RPC与所有静态资源一致。`--restore`同时恢复对应登录入口；不会覆盖其他下载设置。自定义端口、外部修改配置、已有不完整目录均拒绝自动覆盖。Docker模式尚不自动配置登录代理，`--login-page on`会明确拒绝。

本地整合测试：构建 `lab/Dockerfile.login-installer-test` 后，在无网络容器内运行 `tests/install/login-integrated.py`。使用真实Transmission与nginx、模拟DSM套件启停接口；不能替代DSM升级/重启持久化验收。

## DSM 管理员主目录启动修复（2026-11-16）

旧预览版 `2.0.0-nas-preview.20261116.3` 在管理员个人目录启动后，切换到 `sc-transmission` 时继承了服务账户不可访问的工作目录。实机日志显示 `find: cannot get current directory: Permission denied`，随后接入失败并进入恢复。修复在接入前及服务账户资源检查前切换到 `/`，不扩大管理员主目录或 Web 资源权限。套件重启前后增加进度输出，覆盖安装和恢复流程；这不代表已经验证旧失败事务的恢复结果。

`npm run test:installer:cwd` 在无网络、自动清理的本地容器中切换到非特权账户：移除修复的负对照必须报工作目录权限错误，修复后的检查必须通过，真正不可读的 Web 文件仍须拒绝。需要本地 `twui-lab/synocommunity:4.1.4-32` 实验镜像。该测试的系统 find 报错措辞与 DSM 不同，但复现相同的工作目录权限条件。

用户在 DS923+、DSM 7.4.1、SynoCommunity 4.1.4-32 上执行 `2.0.0-installer.4`，确认完整备份、套件重启、页面和 RPC 验证通过；随后通过普通 SSH 独立核对 current 指向该版本且全部发布文件摘要通过。浏览器人工验收、实际恢复、NAS 重启及套件升级保留仍待验证。旧 `nas-preview` 发布附件不会因本地修复而自动更新，不应继续使用旧附件。

用户入口为发布附件 `install-transmission-web-ui.sh`。下载此单个文件到NAS，执行：

```sh
sudo sh install-transmission-web-ui.sh
```

正式附件内置同次发布的预编译静态包；无须另找归档或三个辅助脚本，NAS无须Node.js、Python、npm或Compose。脚本会提示环境选择、认证及必要重启确认。不要将源码仓库中的小型开发入口误认成携带离线包的发布附件；后者由 `scripts/release.mjs` 自动生成。公开Release附件须实际上传后才能从GitHub下载，本地生成不等于已发布。

脚本负责：检测套件/容器和真实原Web目录、页面及RPC握手；核对工具、磁盘空间、归档路径/类型及完整摘要；备份整个旧Web资源和接入信息；安装到独立目录；确认后接入/必要重启；逐个核对新静态资源与只读RPC。普通错误或中断会恢复原接入并再次验证。所有备份持久保存，目录仅root可读，可能包含容器凭据，不要公开上传。

支持SynoCommunity Transmission 4.1.4-32及本机独立Docker容器。套件通过实际进程XDG路径接入，不改供应方脚本；已有XDG旧界面原样移至同目录保留位置，并另外保存完整内容副本。Docker通过Engine结构化配置保留镜像ID、环境、卷（含匿名卷）、端口和网络等字段；旧容器停止后保留，新容器验证失败则移除新容器（不删卷）、恢复旧容器。已有受管理Docker安装升级只切换资源，无需再次重建容器。

自动操作前会拒绝无法安全处理的环境：未知套件版本、现有环境变量强制Web根、无法核实的旧目录、远程Docker、Compose/Swarm管理、自动删除容器、随机宿主端口、静态容器IP、共享其他容器网络、冲突挂载、配置/默认下载/未完成及现有任务目录不在持久化挂载内、容器存在未知可写层修改等。仅挂载根目录及Transmission临时session文件允许重建，不忽略其他镜像内自定义文件。拒绝会明确解释，发生在切换前，不猜配置、不删除原环境。这些边界不表示对应daemon/UI不兼容。

恢复使用同一个脚本和安装结束时给出的备份路径：

```sh
sudo sh install-transmission-web-ui.sh --restore /安装器打印的备份目录
```

备份目录中的状态记录用于处理中断。失败后若恢复尚未完成，会明确输出此命令；不会把“已复制文件”冒充“恢复成功”。遇到原容器被外部替换、备份损坏、原容器已删除或旧资源已被外部修改等情况保留现场，不删除无关容器。`SIGKILL`或断电无法运行退出处理，再次恢复时识别并清理已死亡进程的安装锁。原容器/备份不要在验收前删除；脚本不会自动清理它们。

恢复仅恢复Web接入，不恢复下载任务/daemon设置，不撤销用户已经执行的RPC修改。浏览器标签、偏好不属于静态文件，不由此脚本迁移或清除。首次服务重启可能短暂停止传输，脚本会先提示；`--yes`表示接受该提示，不跳过安全检查。认证通过隐藏输入及临时私有curl配置处理，不把密码放到命令参数或日志。

高级模式仍可指定 `--archive`（同名.sha256或--sha256）、`--url`、`--version`、`--prefix`、`--endpoint`、`--container`。不带内置包的开发入口默认获取GitHub Release的固定附件名`transmission-web-ui.tar.gz`及其`.sha256`，下载失败会在切换前退出。`--check`只做原环境只读预检，不安装或重启。

构建交付时复用明确的冻结Web目录，避免并行开发的dist变化：

```sh
node scripts/release.mjs --version 2.0.0-installer.3 \
  --web-dir .lab/shared-compatibility-verified-release/web \
  --output-dir artifacts/installer-2.0.0-installer.3
```

该命令不运行UI构建。输出版本包、通用下载别名、摘要、携带离线包的单文件脚本及其摘要。包内记录UI版本与安装交付版本；安装交付版本使用独立后缀，不覆盖已有同名不同内容的安装。已安装版本再次接入须摘要一致；存储损坏版本不能用于回退。

真实DSM的ACL、synopkg实际行为、设备重启与升级保留仍需首次使用核对。本机测试只使用一次性容器、真实4.1.4及固定上游服务脚本；模拟的synopkg接口不等于真实DSM认证。

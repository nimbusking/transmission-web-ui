# 旧版数据迁移

新 UI 使用独立的 schemaVersion 2 数据，按 RPC origin + pathname 隔离。同一服务换部署路径时需保持 RPC 外部地址一致，或从原实例导出后在新地址导入。不同协议、主机、端口属于不同浏览器 origin，不能直接读取对方的旧本地存储；先在旧入口导出 JSON 文件。

## 迁移步骤

1. 保留旧 UI 和旧浏览器数据；在原入口导出配置作为额外副本。
2. 新 UI 的“设置 → 本地数据”中检查旧数据迁移，或选择原导出的 JSON 文件。
3. 查看标签数量、目录字典、迁移提示与不支持的内容。只有明确导入后才写新存储。
4. 导入前会同时保存原始输入与已有 v2 设置。通过“导入备份记录 → 导出备份”取得 JSON；损坏的旧 JSON 原文保留在 originalStorage 中。
5. 若包含 server 部分，先导入本地内容不会修改 daemon。另开“应用服务端变更”，核对当前/导入值差异，确认后才发送白名单字段。
6. 重新加载检查结果。旧 localStorage 键不会删除，切回旧 UI 时仍可使用。

## 数据语义

| 内容 | 迁移策略 |
| --- | --- |
| 标签 | 转为稳定 ID，保留名称、说明、颜色，按 hash 维护任务映射 |
| 历史标签数组错位 | 无法推断历史意图，按现有位置迁移并报告悬空索引，保留原文 |
| 目录字典 | 支持仅字典导入，去空白与重复，不清除已有标签 |
| 列布局 | 按字段 key 维护可见性、宽度与顺序，补充新列；完成大小保持 totalSize-leftUntilDone 语义 |
| 旧错误配置 | 预览/校验失败时保持现有设置和旧键，便于修正后重试 |
| daemon 配置 | 独立差异确认，仅写明确支持的可写字段，忽略服务端只读字段 |
| 重置显示偏好 | 仅重置 UI，不清除标签、任务映射和目录字典 |

IndexedDB 更新使用事务，跨标签页通知后重新读取已提交状态。不同字段并发更新不丢失其他字段；同一字段同时编辑以最后一次提交为准，导入前应关闭其他正在编辑该字段的页面。存储不可用时界面显示提示，仅本次会话内有效。

## 目录匹配与回退

目录匹配仅适用于已暂停且元数据完整的任务，使用 move=false 定位，不搬运文件。部分匹配会暂停该项等待决定，其他项继续。取消停止后续命令，已经送达 daemon 的校验可能仍在进行；不要把取消当作回滚。

“恢复原目录并校验”是一个显式操作：重新定位原目录，等待实际校验结束后才标记 restored。恢复目录不表示原目录必然拥有全部数据；界面同时保留完成比例。若失败、超时或取消，作业保留待确认/取消状态，避免误报成功。

刷新页面后保存的运行中作业转为 interrupted，不自动重放。使用“核对并继续”前应先等待 daemon 校验结束并暂停任务；系统重新按 hash 核对当前 id 与服务端状态。旧 UI 的浏览器数据与新匹配日志互不覆盖。

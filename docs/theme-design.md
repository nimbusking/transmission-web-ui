# Transmission Web UI 主题设计规范

本规范区分三个独立层次：布局决定区域位置，视觉主题决定整套UI风格，明暗决定亮度。三项选择组合生效，保留既有布局偏好，不要求重置配置。后续扩展必须遵循本文件并补实际验证，不把规范写完视为验收通过。

## 设置层次与入口

| 层次 | 入口 | 保存字段 | 职责 |
| --- | --- | --- | --- |
| 布局 | 右上“布局” | `ui.layoutTheme` | 页头/工具栏/导航/任务区的区域组织和外部留白 |
| 视觉主题 | 右上“主题” | `ui.visualTheme` | 按钮、输入、菜单、导航、表格、进度条、标签页和弹窗的统一风格 |
| 明暗 | 左下太阳／月亮 | `ui.theme` | light / dark / system，独立于上述两项 |

三项组合生效、分别保存。视觉主题面板提供“明暗跟随系统”，仅恢复system。左下按钮表示下一次切换目标，按当前有效明暗切成明确相反模式并保存。左下仅保留唯一明暗图标按钮；品牌/版本统一移至全宽底部状态栏右侧，不再占用侧栏或与按钮堆叠。桌面专注轨道保留明暗入口；手机端明暗按钮收进侧边栏，仅在导航展开时显示，关闭时不占用分页区域。

## 当前视觉家族

| ID | 家族 | 控件与层次特征 | 配对 |
| --- | --- | --- | --- |
| `modern` | Modern | 6px轻圆角、清爽中性面板、轻边框；青绿强调 | 浅/深 |
| `metro` | Metro | 0px方正控件、扁平面板、清晰线条、无弹窗阴影；红色强调 | 浅/深 |
| `material` | Material | 18px圆润按钮、10px填充输入/面板、浮层阴影；靛蓝强调 | 浅/深 |
| `cupertino` | Cupertino | 8px圆角、细边框、分组控件、轻渐变和层次；蓝色强调 | 浅/深 |

这些是风格家族。以后可以给Metro增加颜色变体，但不得把四种相同形状、只换主色的预设当作四个不同家族。新增家族至少在控件形态、边框/填充方式、表面层级/阴影三项中改变两项；固定布局和明暗后仍应明显可辨。命名描述设计特征，不宣称使用对应厂商的官方组件或完整实现其设计系统。

## 覆盖要求

视觉主题须覆盖页头/工具栏、导航正常/选中/焦点态、按钮正常/悬停/禁用/主操作、输入与选择框、下拉菜单、表格表头/行/选中态、矩形进度条外观、标签页、标签、对话框和提示。不得只改变背景和主题按钮，而让弹窗沿用另一套皮肤。

同一套皮肤的颜色、圆角、表面和阴影来自单一配置。错误/警告/成功/连接状态保留语义颜色；主题强调色不能让错误看起来成功。复选框保留方形或轻圆角，不与单选框混淆。用户指定的全列宽矩形进度条保持20px高、0圆角及原有进度含义；不得改成胶囊条或引入装饰假进度。

## 实现与单一来源

- `src/domain/visual-themes.ts` 提供视觉ID白名单、深浅palette、控件圆角/阴影及类型化 `GlobalThemeOverrides`；`src/domain/themes.ts` 仍只注册布局ID。schema和选择器清单引用相应常量，不另写不同白名单。
- `App.vue` 解析有效视觉主题/明暗，给Naive Provider传递覆盖和 `skin-<id>-<light|dark>` namespace。CSS语义变量同步到文档根，使Teleport的菜单/对话框继承同一palette；卸载恢复原根变量。禁止新建轮询、重复matchMedia监听或业务组件副本。
- 自有视觉样式在 `src/visual-themes.css`，布局仍在 `src/themes.css`。视觉样式不改变grid列/行、组件挂载身份、任务数据或布局选择；布局样式不强行固定视觉色彩。
- 共享变量：`--surface`、`--canvas`、`--subtle`、`--border`、`--text`、`--muted`、`--accent`、`--selected`、`--header-surface`、`--table-head`、`--brand`、`--primary-text`、`--skin-radius`、`--control-radius`、`--skin-shadow`。品牌图形不换形，只跟随强调色；流光用 `--brand-glow`。
- 预览使用同一个profile生成变量，四家族展示同一种界面结构下的真实风格特征；布局选择器另用结构示意。禁止加载外部字体、CDN、图片主题包或旧EasyUI CSS。

## 字体、状态与可访问性

主字号13px，字体使用本地系统回退，不以主题切换缩小正文。普通文字在主要表面上、辅助文字在surface/subtle上、主按钮文字在正常/悬停/按下背景上的对比度至少4.5:1，以自动化测试核对实际palette；禁用态单独保持可识别。必要状态不能只靠颜色。

两个右上入口和左下按钮保留36px点击区域、可访问名称和提示，装饰SVG aria-hidden。主题/布局项使用原生按钮与aria-pressed，Tab/Enter/Space可达；关闭弹窗恢复焦点，隐藏缓存控件不进入可访问树。不播放全页面缩放/位移动画，减少动态效果时取消新增控件过渡；Logo与列设置已有约束继续有效。

深色顶部搜索框使用可辨的subtle底色与默认实体边框，边框相对面板和输入背景对比度至少3:1，占位文字至少4.5:1；hover/focus用皮肤强调色，不能只在聚焦后才出现轮廓。此局部增强不强制所有输入控件使用相同边框。

## 业务和性能边界

所有组合复用唯一Workspace、SidebarNavigation、TorrentTable、DetailPane。不重新挂载工作区，不清勾选/详情/搜索/筛选/分页/列设置/标签/导航展开。保留现有导航筛选清勾选规则。

视觉主题不修改虚拟列表行度量、列宽、分页容量、分块上限、RPC、操作目标、确认流程或调度。DataTable单元格padding及进度条尺寸保持不变；阴影/边框不撑高行。真实当前Naive行约35px，不能因皮肤变高；32px虚拟配置既有限制仍独立记录。浮层不能被父级overflow/transform裁切。只在实际改变性能路径时安排规模/长测，不把局部样式回归说成压力测试通过。

## 自适应与保存

<768px两入口缩为仅图标但保留可访问名称，左右不得被裁切；四布局共同使用移动内容且保存布局ID，回桌面恢复。支持1440/1024/800/390px及强制桌面模式，工具栏/表格各自滚动，整页不横向溢出。

沿用origin+RPC路径隔离的IndexedDB字段事务、BroadcastChannel通知和v2导入导出。新增visualTheme缺失/未知回modern；layoutTheme缺失/未知回workbench；保留历史theme明暗。旧客户端可能忽略新增字段，后续再次升级安全回默认；不清数据库。写入期间阻止同一选择器重复提交，失败可见，存储不可用时沿用原有内存降级提示，不承诺跨重启保存。

## 扩展主题步骤与验收

1. 在OpenSpec说明家族特征、覆盖控件、深浅palette、自适应和兼容策略，增补任务。先确定风格差异，不把布局变体作为视觉主题。
2. 更新视觉注册表、profile、类型化Provider覆盖、中英文名称/描述及自有CSS。预览读取同一profile；添加必要对比度测试。
3. 固定同一布局/明暗，检查四家族按钮、输入、表头、导航、选中、进度和弹窗的可观察差异。检查Teleport菜单/选择框/缓存列设置随皮肤同步，不能只断言根class。
4. 验证所有布局×皮肤组合、两种明暗、手机入口、强制桌面、键盘/焦点、减少动态效果、当前勾选与详情身份。检查主题切换前后布局坐标/行高不变。
5. 验证旧v2、未知ID、三项并发保存、刷新、跨标签页通知和导入导出，记录无daemon写入或第三方请求。
6. 运行相关unit、三浏览器mock、类型/生产构建、lint/格式、OpenSpec strict、old完整性和资源预算。冻结dist直到测试结束，保留实际样式/几何和页面截图；不要在测试中途重建资源。
7. 更新本规范主题表和验证/进度，生成完整离线资源，按已有授权切换静态入口。安装运行不需Node/npm/Python/CDN；不改任务/daemon，不启停对照容器。真实DSM与原性能未达标项继续独立记录。

## 底部状态栏规则
所有布局必须保留全宽独立末行（32px加底部安全区），不得随主列表横向滚动或被详情/导航遮挡。左组下载、上传、可用空间，配14px按需SVG图标；右组连接、Transmission版本、RPC及UI版本，组内竖线、左右弹性间距。窄屏仅状态栏内部横向滚动。用header-surface/text/muted/border/accent语义变量适配四皮肤及明暗，不能硬编码白底/黑字。有效0与未知分开，断线标过期；空间提示默认下载路径，禁止伪造数据或用浏览器存储额度代替daemon磁盘。

文件控制区遵循表格/表单/菜单的Provider和语义颜色，局部宽度须用有作用域的选择器覆盖组件运行时宽度；桌面避免无谓换行，窄屏允许换行且为左下明暗按钮留足空间，不能挡住正则/搜索或批量操作。主题回归应包含万文件分页与全部四皮肤明暗窄屏截图。

## 登录主页

登录入口采用“纯粹极简”：居中品牌标志与320px表单、无外层卡片、大面积留白，顶部语言选择、底部明暗切换。复用现有主题Provider、品牌组件与语义变量，移动端允许页面纵向滚动，输入字号不低于16px。

启动仅加载配置和偏好，默认停留登录页；无论服务器是否启用认证，均由用户提交表单后才连接RPC并进入工作台。401/403时显示登录页、停止后台轮询，凭据成功后恢复；认证失败和连接错误分开显示。密码输入在提交结束后清空，Basic凭据只驻留RpcClient内存，不写入设置或浏览器存储。

RPC请求使用显式Authorization和`credentials: omit`，不依赖浏览器HTTP认证缓存，也不携带Cookie。依赖Cookie的反向代理单点登录需另行适配。若HTML或静态资源本身被HTTP Basic保护，浏览器可能在应用加载前显示原生认证窗口；要完整使用此登录页，部署入口需要公开静态资源并继续保护RPC。这次变更没有修改服务器认证配置。

验证：`npm run check`；`tests/e2e/login.spec.ts`覆盖错误密码、清空密码、手机窄屏、深浅切换与成功进入工作台，RPC/Store单元测试覆盖凭据清理与认证失效后重新登录。

## 手机端表单与任务勾选

手机任务列表使用独立的内容/勾选框选择器；勾选框可见方框与卡片垂直中心对齐，点击区域至少44px，勾选事件不冒泡打开详情。600px以下配置表单的短值行改为上下排列，避免文案/数值/单位互相挤压；桌面仍沿用紧凑列布局。手机或触控设备的登录/配置输入采用16px字号，主要表单操作采用44px触控高度。导入文件控件在手机上上下排列；服务端差异确认在600px以下按名称、当前值、导入值逐项展示。时段输入使用真实label关联，不依赖组件不支持的input-props。验收范围、问题及真机验证边界见[手机端验收](mobile-ui-acceptance.md)。

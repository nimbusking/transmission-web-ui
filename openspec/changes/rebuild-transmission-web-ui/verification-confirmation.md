# 重新校验二次确认与逻辑核对（2026-11-16）

## 调查与范围
Workspace.commands的verify直接映射torrent-verify，工具栏/更多/右键均走operate并立即execute，缺少确认。store.targets捕获id/hash/generation，command写前校验身份并以hash发送，execute对verify串行、重读列表，未知网络结果不自动重试；进度列使用recheckProgress。RPC成功只表示接受请求，不等于磁盘校验完成。

直接重新校验改为复用ActionDialog：先捕获点击时明确范围，弹框显示数量、任务名、磁盘I/O与耗时提示、提交与完成区别；默认焦点取消，明确点击“开始校验”才发送。取消/Esc/关闭/点击遮罩均不写。不得因后来勾选或高亮变化扩大目标；确认时继续校验原hash/generation，失效拒绝。忙碌锁和submit重入保护避免双击重复发。失败保留原目标/错误，并禁用该窗口再次提交整批，避免部分成功时把已接受项再发一次；提示先核对状态并重新选择需要处理的任务，unknown不自动重发。成功文案说明已提交，请观察任务状态，不能暗示实际校验已完成。

改目录后显式勾选“完成后校验”已经包含在改目录确认中，补同一I/O/提交含义提示，不再增加嵌套确认。目录匹配是用户显式启动的多步骤作业，内部校验沿用既有流程，不在底层command加入交互弹框，避免阻断作业/恢复。

## 顺序和验收
1. 更新规格/任务并核对所有verify调用点；不改old/和已有未提交内容。
2. 将verify移出Workspace立即命令映射，ActionDialog处理该动作、明确确认按钮/提示及取消焦点；复用冻结目标、错误显示和既有串行批量。
3. mock浏览器覆盖三个入口、取消/Esc/遮罩、确认前零请求、单/多任务hash范围、目标在确认中变化、双击、失败、校验进度与批量取消。底层unit检查空目标/身份/unknown及串行行为。
4. 四个已缓存镜像各启动一个一次性离线容器，无端口/共享卷/宿主数据挂载；仅自建32KiB两分块任务，测试一块有效/一块损坏后haveValid=16KiB、修复后32KiB，并等待实际校验结束及核对位图/文件未被改写。停止并删除自己的测试容器，不操作twui-compare或twui-lab服务。
5. 完成相关静态、构建、旧摘要与预编译归档；按本次工具栏验收更新已有授权直接切换19081，不额外备份。实页只打开并取消确认框，不提交真实任务校验；记录证据、限制、回退和用户待验。

## 边界
不新增轮询/后台/目标依赖，不修改任务状态或daemon设置，不重复无关压力长测。现有13.12性能和DSM真实设备待验保持开放。已接受的校验不能通过关闭对话框撤销，提交中确认框内提供取消后续任务（原页面底部入口会被遮罩挡住），只停止后续提交；提示不把RPC响应当校验完成。已有较早before-table-progress快照可回退，但无本次精确前一版新备份，回退会撤销之后外观/交互修正。

后续更多菜单改为仅全局启停/Tracker替换后，直接校验只保留工具栏与完整右键；确认逻辑继续覆盖这两个现存入口，不再在更多重复显示。

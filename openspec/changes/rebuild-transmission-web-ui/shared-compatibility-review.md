# 共用修复计划交叉核验与收敛记录

## Status / Conclusion

2026-11-16：仅审查与修订OpenSpec，没有开始实施、业务测试、构建或发布。依据当前工作区源码、现有测试断言、3.00审查证据及官方协议交叉核验；不是对尚未编写的代码作兼容性保证。

原计划覆盖了已识别的主要问题，但存在两项不必要的行为变化和若干未写清的回归边界。**修复必须围绕已有故障，不能把全部版本降到最低能力，也不能为了数字统一而改变功能含义。** 本记录约束[详细设计](shared-compatibility-fixes.md)D1–D9及[tasks](tasks.md)第30节；27项仍全部待实施。D4/D5的旧规划已被本次修订替代，不影响既有实现历史记录。

## Subsequent Decision: C11 能力挡板

用户补充授权的是**设计支持边界**，不是立即修改界面。新增D9：差异过大的非核心子能力允许按连接/RPC能力屏蔽；这修订了C8和原D6中“3.00所有删增组合必须实现”的隐含要求。纯URL替换及读取保留，3.00任意分组屏蔽，混合替换/删除/新增默认整体拒绝；单独增删以定向证据决定开放或挡板。临时错误不等于不支持，4.x正常能力不能被最低版本限制。

对应30.13/30.16/30.17/30.20–30.26：UI与提交层共同拦截、跨generation重算、不探测性写入、不持久化全局降级。验收区分“已支持”“受限且已验证”“延期”；核心正确性问题不能以挡板代替修复。详情/能力范围与验收以[设计D9](shared-compatibility-fixes.md)为准，27项仍未实施。

## Explicitly Deferred / Remaining Limits

- 原审查A06截断分块位图、复杂正则/超大文件首载、串行慢磁盘刷新：明确保留为独立待办，本轮不改PieceMap算法、不加worker/后端分页、不重写轮询；非遗忘、非已修复。正常分块功能仍须回归。
- 极大限速值的跨构建边界尚需定向核实，未凭4.x版本号猜平台位宽。它是限速实现验收前的待决数值规则，不授权升级daemon、探测宿主或操作用户任务。
- 协议无CAS/实例代数：预检后外部写入仍有窗口；同hash任务在未被观察期间删除再加回且ID也相同，不能宣称客户端必然识别该次生命周期变化。明确观察到移除后使旧选择失效；不为极端窗口新增后端或频繁全量轮询。
- 正常Tracker服务端可能规范化组号/重分配ID，按文档D6语义核对；若实际返回产生额外规范化，先记录可复现例子，再限定比较规则，不为让测试通过忽略真实成员/组变化。
- 本轮没有发现需要整体取消UI或移除现有正常功能的依据；也没有验证过尚未实现的修复。只有未来同构建回归通过，才能确认这些边界被正确执行。

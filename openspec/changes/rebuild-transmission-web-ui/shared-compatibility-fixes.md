# Transmission 3.00 / 4.0 共用问题修复设计

## Status

2026-11-16（Asia/Shanghai）：**仅完成设计，实施未启动**。用户明确要求“暂时先不执行”。本文件与tasks.md第30节是后续实施依据，不构成开始编码、运行业务验证或发布的指令。所有新增实施任务保持未勾选；本轮只允许修改OpenSpec文档并做规格校验。

本设计追加到现有未归档变更`rebuild-transmission-web-ui`，避免另建依赖尚不存在主规格的修复变更。既有实现记录仍是历史事实；本节是待实现的目标行为，不能用规格已写完代替代码已修复。

2026-11-16交叉核验补充：[收敛与回归审查](shared-compatibility-review.md)。本次审查修订D4、D5并补充D8；后者是实施约束，不是扩大修复范围。后续按用户要求新增D9能力挡板：差异过大的非核心能力可明确屏蔽，不强制补齐；与此前强制实现措辞有冲突时以D9为准。

## Context

审查入口：[3.00行为评估](../../../docs/transmission-3-ui-review-2026-11-16.md)；证据为`docs/validation-evidence/ui3-native-audit.json`、`ui3-audit-diagnostics.json`、`ui3-review-summary.json`。现有发布SHA-256为`cf927e7a81040fcd1b2b2cfdd030d9167787549ea61aa1872da8504ea9e0c179`。

3.00真实小样例确认：总大小32768字节、仅下载其中16384字节、其余文件跳过；`leftUntilDone=0`，旧公式却计算已完成32768字节。受控诊断另复现勾选身份转移、3.00只改Tracker分组不发送写请求、RPC17并发分组覆盖等问题。现有限速字段能在3.00提交并读回，不应将固定默认值造成的误覆盖归咎于daemon不支持。

关注实际表现与数据含义，不以接口覆盖率为目标。3.00和4.0.0/4.0.6使用同一修复模型；保留当前4.1.4环境的既有行为。3.00的Tracker分组限制是必要的版本差异保护，单独处理。

## Goals / Non-Goals

**Goals**

- 选择身份从用户点击开始稳定，任何入口都不能把旧选择转给新任务。
- 列表/概览/移动展示的已完成数据、未知值和Tracker人数有统一且可解释的口径。
- 单任务限速展示真实当前值；批量限速只修改用户明确指定的方向。
- Tracker保存检测并发编辑、核对实际结果，3.00不再无操作却报告成功。
- 错误、部分成功、结果未知和取消有明确恢复方式；保留原分页、主题、自动刷新与其他任务操作。

**Non-Goals**

- 不恢复已移除的任务配置tab，不重新开放分享率/空闲时限表单。
- 不升级daemon、不迁移协议、不修改daemon全局默认值、站点或种子内容。
- 不改变总大小1024换算/KB标签约定、下载百分比的daemon定义、文件原始index或分块聚合算法。
- 不新增文件后端分页、正则执行引擎、磁盘轮询架构或主题布局改版。
- 不扩展到DSM实机、旧浏览器、依赖审计或接口清单；既有13.12性能待办不因本轮修复自动结案。

## Decisions

### D1. 从勾选开始绑定身份，数字ID只作为界面索引

选择的权威数据为`{ id, hashString, generation }`集合。保留界面所需`checkedIds`视图，但由store统一选择API生成，组件不得直接写任意数字ID数组绕过身份捕获。`setCheckedIds/toggleChecked/clearChecked/captureCheckedTargets`为职责示意，具体命名在实现时保持一致即可。

1. 表格单选、全选、Shift、移动入口均在点击时捕获当前行身份。没有完整hash的行不可选为写目标。
2. `DYNAMIC_FIELDS`加入`hashString`，在正常增量中就能识别ID复用。现有全量与补齐链保留；不为每行增加请求。
3. 同ID返回不同hash时，实体按新对象建立，不将旧任务目录、Tracker、计数等缺失字段合并给新任务；身份尚不完整时只读并补齐；仅目录等非身份字段缺失不阻断已有安全操作。
4. 移除/身份变化时只清理失效选择；对应详情关闭、取消加载并递增序号；Shift锚点和已打开右键范围失效。有效其他勾选保留，不触发任何自动命令。
5. 详情请求按选中hash读取并同时核对hash/generation/请求序号。晚到的同ID旧hash响应同样无效。
6. 工具栏从冻结选择集合取目标；右键菜单打开时冻结范围；行内标签/文件操作捕获该行或该详情身份。全局启停仍先全量读取，再冻结并确认全部范围。
7. 同hash、同generation的名称/速度/排序变化保持选择；同hash换了数字ID不静默迁移选择，重新选择后才允许写。重连仍清空临时选择，不迁移到新generation。
8. 已发送命令只按hash寻址。服务端已删除目标时不能退回数字ID或扩大为全部；空目标始终拒绝。未观察到的外部变化仍可能发生，hash寻址和写前读取用于缩小风险，不声称客户端拥有daemon事务。

本地标签仍按hash保存；清选择不删除旧hash标签。匹配作业持久化格式不改，恢复时仍显式重新核对身份。新选择集合不写IndexedDB，不需要迁移用户偏好。

### D2. 已完成列统一表示当前持有的数据量

保留列key`completeSize`、默认列顺序和既有布局，显示名称仍为“已完成”。其统一定义为：

`completeSize = haveValid + haveUnchecked`

含义是daemon统计的当前持有数据，包含待校验部分；不是历史累计下载量，不是已选文件目标大小，也不是磁盘预分配/占用空间。表头/概览提供相同说明，概览继续单列显示已校验与待校验数据。

| 数据 | 口径 |
| --- | --- |
| 总大小 | `totalSize`，保持原值与单位标签规则 |
| 已完成 | 当前`haveValid + haveUnchecked`，包括已跳过文件中实际仍持有的数据 |
| 下载进度 | 继续使用daemon的`percentDone`，针对所选文件 |
| 剩余量 | 继续使用`leftUntilDone`，针对所选文件 |
| 历史已下载 | `downloadedEver`，不作为当前持有量替代 |
| 分块图 | 完整分片位图；不承诺与含待校验数据的完成字节比例相等 |

- 列表动态读取加入`haveValid/haveUnchecked`，概览已经读取则复用；共享纯函数派生，列表/概览/移动端及排序一致，不增加逐行详情读取。
- 两个加数必须为非负安全整数字节，和也须安全；若同身份元数据已就绪且有可信有效totalSize、和大于总大小，则结果未知，不能夹断为貌似正常的数值。totalSize未知不妨碍两个有效持有量求和，但不推导比例。
- 任一必要字段缺失/负数/非有限/非法类型时显示`—`；已知0显示真实0。不能退回`totalSize-leftUntilDone`或以0补缺项。
- 增量没有请求该字段时可以沿用同身份旧字段；本轮明确请求却遗漏/返回无效时必须转为未知，不能沿用旧成功值。读取适配层须区分“未请求”与“请求但无值”。
- 例：32KB总量、16KB完整/16KB跳过无数据，显示16KB持有和100%所选任务进度；若跳过文件原来就有数据，则持有量保留该部分。正常下载未完成、校验中、零字节和元数据未齐均使用同一规则，不按状态伪造字节。

不通过改成`sizeWhenDone-leftUntilDone`掩盖问题；该公式表达所选范围的完成量，不能准确表示当前全部持有数据。已有只含一个文件的正常样例应保持原结果。

### D3. 未知与0分开，保留各字段特殊含义

引入共享计数/字节展示规则，复用现有有效数值判断；NaN、Infinity、缺失、非法类型和负数哨兵显示未知。计数额外要求为安全整数。列表、概览和移动端使用同一派生结果与格式器。

- 种子/下载报告数、活动连接数、概览下载百分比去掉伪造的`?? 0`。百分比未知显示`—`；合法0仍为0%。
- 人数左右两项独立校验，例如报告未知但有2个下载连接，显示`— (2)`，不能整体变成0。
- 文件下载状态与优先级若字段缺失，显示未知，不把未知当跳过/普通优先级；保留wanted数字/布尔归一化。
- 分享率`-1/-2`、ETA、状态码等继续按各自定义处理，不能用一个“负数都无效”通用规则破坏其既有语义。
- 同连接网络失败仍保留缓存并标记过期；成功回读明确未知则显示未知。这两种情况不得混同。

### D4. 保留Tracker报告合计口径，只澄清其含义

交叉核验收回原计划的“取最大已知值”。原审查证明求和不是去重人数，并未证明max更接近真实人数；改成max会无必要地改变当前列表数字和排序。本轮保留原有效报告求和策略，不新增统计策略开关。

- 同任务、同种人数：所有Tracker报告均为非负安全整数且和安全时显示合计。两个10仍为20，10和20仍为30；提示“Tracker报告合计，可能重复统计，非去重人数”。
- 任一报告未知则合计仍为`—`，不把已知部分当完整合计；无Tracker为`—`，所有报告为有效0则显示0。人数左右两项独立，不清空有效活动连接数。
- 保留`seederCount/leecherCount`列key、宽度、顺序、短表头“种子 | 活跃”“下载 | 活跃”；只增补表头/概览说明，不通过增长表头破坏110px默认列宽。左值明确为报告合计；右值分别为向本机发送/从本机接收数据的连接数，不声称是左值的精确子集。
- 逐Tracker详情、导航按任务去重、刷新节奏均不变。不新增scrape请求，也不把缓存报告称为实时精确人数。提示/日志不附加含passkey的地址。
- 列表/概览/已有移动展示复用该派生及未知排序；不为“统一”新增移动端原本没有的数据栏目。聚合策略重新选择属于将来独立需求。

### D5. 限速使用方向独立、默认不修改的编辑模型

保留工具栏“传输限制”，不重建任务配置页。弹框显示冻结任务名称/数量；单任务加载真实当前配置，多任务汇总“相同值/不同值/不可用”。下载与上传两行，每行模式为：**保持不变 / 不启用本任务限速 / 限制为**，默认都为保持不变。

“不启用本任务限速”仅关闭该任务方向的限制，仍可能受全局或备用限速影响；界面不可简称为“实际不限速”。不修改`honorsSessionLimits`或任何全局字段。

| 用户意图 | 提交规则 |
| --- | --- |
| 保持不变 | 该方向不提交任何字段 |
| 不启用本任务限速 | 只提交该方向`*Limited=false`，保留已有数值 |
| 限制为N | 提交该方向`*Limited=true`和`*Limit=N`；按每个任务当前值省略完全无变化的字段 |

- 单任务“限制为”可带入实际已存有效值；多任务值不一致或不可用时数值留空，不预填100。保持不变时可查看只读当前值，不暗示已修改。
- N为非负安全整数KB/s；显式选择“限制为0”保留现有可表达能力，并就地说明“启用且为0可能阻断该方向传输”，不得解释为不限速。默认保持不变不提交已有0，也不擅自修正。
- 收回对全部版本统一设置1–4,194,303 KB/s上限的方案。4.0.6内部速度类型为平台相关的size_t，不能由版本号推断所有构建具有相同数值边界。上限是30.9/30.21/30.22的定向核实项：检查目标版本转换/溢出及隔离回读，记录确定的拒绝条件后才固化输入校验；不把3.00推算保护值直接套到4.x，不新增位宽探测RPC或向用户任务写极值。已存较大值可查看/保持/关闭限制，不夹断写回；不得将尚未核实的极值支持宣称已完成。
- 空白/负数/小数/NaN/不安全整数/已确认会溢出的输入禁止提交并就地说明；两个方向都保持不变时确认禁用，取消只关闭窗口。

状态过程：`loading → editing → preflight → writing → readback → settled`；任何阶段关闭/切连接后的晚到响应不得写回另一个弹框或任务。

1. 打开时按hash读取4个限速字段，普通并发最多3；失败保留错误与重试入口。没有有效基线的任务不得进入写入计划，不能默认替换为100；需要重新读取或退出后明确重新选择可用目标。
2. 提交时冻结方向意图，先读取所有目标的最新相关字段。先核对全部目标身份，目标消失/身份失效即停止；有效目标中先将触及字段已符合意图的项列为无需修改，其余所需基线变化时，**本批尚未写入时整体停止**，显示冲突及重新读取入口；不自动丢弃草稿或强制覆盖。未修改方向的外部变化不触发冲突。
3. 每任务生成最小patch；完全一致列为“无需修改”，不发送空patch。保留逐项结果，不把无需修改当请求成功。
4. 从提交开始、首次预检前即获取有归属token的现有批量busy锁，持有至写入/回读结算，普通并发最多3。取消停止尚未发送项，不声称撤回已发送命令。
5. success后按hash回读实际触及字段。匹配才显示已保存；回读不一致显示明确失败，回读失败或写结果未知时显示“可能已应用，需核对”。不自动重试、回滚或再次提交整批。
6. 单项失败不隐藏其他结果。再次修改须显式重新读取新基线；旧确认按钮不能重放整批。共用批量结果可增补原因信息，但不破坏其他操作已有success/failed/unknown/skipped等含义。

daemon不提供CAS。全部预检完成与逐项写入之间仍有外部变化窗口；执行前再次检查本地身份并核对/回读，不承诺原子保存，也不使用旧值自动覆盖回滚。

### D6. Tracker保存核对完整基线与实际语义

单任务编辑和批量替换共用`TrackerSnapshot`：任务身份、按回读顺序排列的`{id,announce,tier}`。分组用组序号标准化比较，忽略无语义的tier编号空洞；URL字符串完整比较，不去掉查询参数、不排序合并不同tier；原始ID必须参与写前身份比较。

1. 编辑/预览开始时冻结完整基线；保存前按hash回读，URL/顺序/分组/ID任一变化则冲突，提交0次；保留草稿并允许用户明确重新载入后再编辑。
2. UI操作期间本地其他同任务修改也受busy锁保护；批量Tracker预览中old/new输入发生变化时使旧预览失效，晚到的旧预览不能重新启用应用。
3. 能力仍以`rpc-version >= 17`分支（覆盖现有4.0/4.1环境），不改成只匹配4.0版本字符串；使用`trackerList`完整提交tier，回读按URL与标准化分组核对；回读不要求ID与旧列表相同，因为daemon可能重新分配ID。
4. 3.00不实现任意tier重排：原分组只读，隐藏自由空行分组编辑，程序边界拒绝tier重排。保留已核实的逐行URL替换；新增/删除及混合保存按D9分别判定，仅开放有证据且代价可控的子能力。不能以不发请求的成功结束，不通过先清空再重建模拟分组。
5. 3.00混合替换/删除/新增默认不作为本轮必须实现项；按照D9设置挡板。只有该组合被明确开放时，才执行先替换、再删除、再新增，每步前后核对有效ID/预期状态，异常停止余下步骤。不得为满足此流程扩建事务模拟器或自动恢复旧表；挡板必须在首个写请求前拒绝整个不支持计划，不能偷偷执行其中一部分。
6. 最终回读：URL变更/成员集合必须符合用户计划；保留组与新增组符合对应版本承诺。3.00中途成功后失败显示部分保存及实际回读，未确定的结果标记未知，不伪装全失败/全成功，不自动恢复旧列表。
7. 批量替换逐任务结算冲突、无需修改、成功、失败/部分保存、结果未知、取消。一个任务冲突不覆盖它，也不取消其他独立任务；批量应用前须已显示原URL→新URL和明确目标数量。失败项必须重新预览才可再提交。
8. 不创建长期保存的含passkey基线。窗口关闭后丢弃临时数据；错误和导出不得额外暴露完整私密Tracker URL。已有页面用户主动编辑/预览的真实地址保持可见，不创建新的敏感日志。

### D7. 版本差异与刷新保持一致

- 3.00的wanted 0/1、4.0.0的布尔值继续归一化；重复添加的返回形式保持现有适配。
- 4.0.0–4.0.5继续约15秒全量核对，其他现支持版本沿用常规策略；一轮耗时另计，不保证外部操作即时出现。明确操作后仍定向核对，关闭自动刷新仍允许手动/操作核对。
- 保留上游分享率计算差异，不为了跨版本数字一致重算分享率。
- 同步字段增补仅增加每任务的hash/两个字节值，不改变用户轮询间隔、不创建新轮询或逐行读取。

### D8. 兼容修复的收敛边界（交叉核验新增）

[交叉核验记录](shared-compatibility-review.md)中的C1–C10与回归矩阵是本节验收依据。

- **身份补齐只影响目标行**：增量未包含的行不清值、不清选择；返回行缺hash时该行临时不可写、保留只读过期内容，不将整个连接判为不兼容。已有hash按hash补齐；新未知行可按ID读基础信息，但返回hash只建立新身份，不能复活旧勾选。补齐响应须比对发起时generation/行修订；目标已经变化时丢弃晚到补齐。失败等待既有下一轮/手动刷新，不递归或逐行无限重试。
- **保留现有选择操作规则**：过滤/翻页/每页数量切换原本清选择的规则保留；排序与同身份常规刷新保留选择。表格当前页全选、Shift可见范围、右键未勾选行的显式范围、移动操作、详情高亮与批量勾选分离均保持。新增身份检查不要求所有详情/右键操作必须先勾选工具栏复选框。
- **缺失值适配限于本轮字段**：只处理本轮持有量、人数、下载进度、文件wanted/priority。不得对所有RPC字段统一清缺项、禁止负值或改单位。fileStats中的wanted仅true/false/0/1有效，不能先Boolean(undefined)变false；缺字段允许按原index从有效wanted/priorities数组回退。优先级-1/0/1全有效，-1是低优先级；已知hash/index的文件可显式设置下载/跳过/优先级，未知旧状态不是永久禁用理由。
- **进度语义分别保留**：桌面校验中进度条继续显示recheckProgress；概览下载进度继续percentDone。共用格式不要求不同语义数值相等，不用持有字节推算百分比、不更改现有移动布局。持有量与totalSize的上界核验仅用同身份且元数据已就绪的可信总量；磁力元数据由未齐转完成时沿既有批量补齐链更新基础数据，不能拿缓存totalSize=0长期把有效持有量判未知。
- **锁不扩大到浏览和编辑等待**：弹框初次读取/编辑草稿不长期占用批量锁；提交预检至结算持有操作token。单项Tracker与批量入口复用执行层，批量只取一次锁，避免嵌套取锁死锁。command内部校验所属token，现有匹配工作流限制继续有效；不新建全局调度器。关闭/取消/失败释放自身token，旧generation的finally不能解锁新操作或覆盖新结果；刷新/查看详情/搜索/主题始终可用。
- **无修改优先识别**：限速预检若触及字段已达到明确目标，列为无需修改；否则才与原基线比较判冲突。冲突集合是意图需要保证的字段：关闭只比较Limited，启用限制比较Limited与Limit，保持不变不比较。Tracker精确无变更不发送写请求、不声称已保存新值；空响应/缺trackers不是有效空基线，明确[]与缺字段区分。
- **正常Tracker变化不误报冲突**：仅比较id/announce/tier/顺序，忽略scrape/通告时间、人数和错误字符串的正常变化。比较器保持URL原文，不做额外清洗/域名归并。写前全列表本地校验，检测本次编辑新产生的重复冲突/无效地址、未知成员ID/不支持的3.00分组计划，不能执行一半才发现本可提前发现的输入问题。明确空列表删除按目标版本现有能力处理，不默认禁止也不擅自伪造成功。
- **409协商与重试分开**：维持RpcClient已有有界409 Session-Id协商；“不自动重试写”仅指可能已送达的网络/超时/协议等不确定结果，不删除409握手，也不增加写入重试。写成功后读失败由新限速/Tracker执行层分类为unknown；预检阶段失败仍是未提交。旧通用runBatch/其他操作结果含义不为本轮重写。
- **4.1.4是必须通过的基线**：用独立一次性4.1.4 daemon覆盖本轮全部变更路径，连同3.00/4.0.0/4.0.6各自行为通过才可交付；19081只做只读对照，不向现有任务写值造回归。发现4.x退化时阻断对应修复交付、缩小/重做该修复，不能通过全版本禁用已有能力让测试通过。

### D9. 差异过大的非核心能力采用挡板，不强制兼容

用户补充决定：保证日常使用和当前4.x体验，比让每个版本出现完全相同的按钮更重要。对于跨版本语义差异大、需要高风险多步骤模拟或大量专属维护的**非核心子能力**，允许隐藏、禁用或保留只读。挡板是一种明确的支持边界，不是“实现成功”的替代说法，也不是用来掩盖前端缺陷。

#### Decision Rules

1. **正常能力保留**：已有低成本且语义清楚的适配（wanted bool/0/1、hash寻址等）继续保留。不能仅凭“3.00较旧”屏蔽整个服务器详情、所有限速、所有文件操作或整个UI。
2. **小差异适配，大差异收口**：只需明确字段映射/显示差异且能验证的，正常适配；需要清空重建、复杂多阶段补偿、伪造结果或无法可靠回读的可选能力，优先挡板。不能预设“必须把所有能力做完”再无限添加兼容分支。
3. **核心故障必须修**：选错任务、未知当0、错误完成量、限速默认误覆盖属于共用正确性问题，必须修正，不能通过隐藏功能逃避。连接、列表/详情读取、添加、启停、选择下载、正常数据展示等日常路径不因可选能力受限而瘫痪。核心能力确实无法可靠工作时应报告阻塞，不宣称整体兼容。
4. **按最小能力隔离**：只关不可靠的子动作/组合；可用的查看、URL替换或单方向限速保留。范围限于有证据的RPC能力或具体实现，不向4.0/4.1扩散；不以永久全局开关降级所有连接。
5. **需要证据才能新增长期屏蔽**：记录差异证据、适用范围、使用影响、保留路径、开放条件和验证结论。先采用本节明确的挡板；其他可选功能若后续发现重大差异，先更新这张决策表再调整，不能凭一次超时或失败自动永久隐藏。

#### Initial Capability Decisions

| 子能力 | 本轮边界 | UI与提交行为 |
| --- | --- | --- |
| Tracker查看、当前组/原始报告 | 保留3.00与现支持4.x的读取 | 即使编辑子能力受限，服务器tab及真实数据显示仍保留 |
| Tracker任意tier重排/自由分组 | 3.00屏蔽；已核实RPC>=17路径保留 | 3.00组只读且无自由分组控件，编辑区简短说明；4.x完整编辑不受影响；提交层再拒绝不支持的tier计划 |
| Tracker纯URL替换（含批量替换） | 继续保留已核实路径，不为混合编辑建立庞大兼容框架 | 明确目标与完整基线，保持组/成员关系，写前预检、写后核对；重复地址等非法变化在写前拒绝 |

#### Implementation Boundary

- 采用一个小型集中能力判定模块，输入已有session RPC版本、必要的已知实现版本和当前generation，输出本轮使用的能力状态及原因。可用`available / unavailable / unknown`表达；未知不等于已经证明不支持。只建上述决策所需条目，不扩成插件系统、远程功能开关平台或全接口清单。
- 已知协议能力优先，版本字符串仅用于已有明确差异。定制/未识别构建不能凭“看起来是4.x”推断全部支持；也不能盲目按3.00降级。会话握手未完成时可选写入口暂不可用，读取成功后重算；能力判断不新增周期探测或任何测试性写请求。
- **稳定不可用**：隐藏无意义的专属按钮/菜单项；在保留的编辑区域说明“当前连接不支持分组编辑”等具体原因，不留大块空白、不展示实现细节。**暂时未知/加载/离线**：必要入口禁用并显示状态或重试途径，不因短暂错误永久消失。
- 工具栏、右键、详情、快捷入口和批量计划使用同一个判定；领域计划/提交层也必须拒绝，不能仅CSS隐藏。受限动作调用产生0次修改RPC，不能落到另一个有副作用的替代命令。批量预览仅展示实际可执行计划，能力变化使旧计划失效并要求重新预览。
- 重连/连接切换后按新generation重新判定，旧弹框/预览失效；不把挡板保存到用户主题/列设置/Settings schema，不提供“强行开启不支持能力”的绕过按钮。单任务输入错误、服务端业务失败、401/403、超时和网络错误均不自动写入全局不支持结论。

#### Acceptance / Stop Conditions

- 3.00受限组合/分组在所有入口均不可提交、0次修改RPC，正常读取、URL替换和其他日常操作可用；4.0/4.1已支持路径不被挡板误关。
- 用同构建切换3.00与4.x连接，能力随generation恢复/收敛，旧计划不得越界；临时失败恢复后不残留永久隐藏状态。
- 若独立新增/删除适配依然差异过大，30.16–30.17交付结果可以是“该版本该子能力已屏蔽且验证完成”，无需强行实现。验收记录必须写明受限能力、依据和保留路径，不能标为“功能已实现”。
- 使用挡板后核心功能仍有退化、或4.x正常功能受损，则候选仍不合格；不能靠不断加挡板把回归失败全部消掉。当前仍为设计阶段，不立即屏蔽线上任何入口。

## Implementation Order / Gates

依赖顺序：**身份模型 → 字节/统计纯模型 → 界面显示 → 限速保存 → Tracker保存 → 合并回归 → 候选交付**。

- G0 当前停留：设计已写入，等待用户后续明确开始实施。先前连续部署授权不改变本轮“暂不执行”。
- G1 模型可用：身份替换/未知/报告合计/持有字节核心测试通过，再接界面；业务命令不得绕过身份入口。
- G2 写操作可用：限速/Tracker预检、部分结果与回读通过，才能进入真实隔离小样例；按D9屏蔽的可选能力验收拒绝路径，不强制模拟实现。
- G3 候选可审：真实行为、相关浏览器与静态检查通过，差异/限制有记录，才生成后续候选包。
- G4 发布：仅在用户解除本轮暂停后，按届时有效授权执行；当前阶段不得生成发布包或更新19081。部署继续仅静态资源、资源先行/入口最后，不修改用户任务或服务生命周期。

每一项拆为可独立审查的提交范围（不意味着本轮提交git），具体待办见tasks.md第30节；不一次性混入无关重构。

## Migration / Rollback

- 不改变Settings schemaVersion、列key、标签hash、文件条数和主题偏好；本轮无自动用户数据迁移。身份集合/表单基线均仅内存。
- 后续发布前记录当时实际运行资产与本轮候选SHA/manifest；不把既有较早快照当作精确上一版。是否创建新备份遵循届时明确指令，不能用规划偷偷恢复“每轮必备份”。
- 静态回退只恢复静态文件和部署记录；用户已经确认的限速/Tracker修改不会随前端回退撤销。不得以旧表单值自动回滚daemon。
- 不删除已有验证证据；新记录必须明确取代了哪些问题结论，未修复项仍开放。

## Risks / Trade-offs

- 同步每行增加hash和两个字节量有载荷/派生成本，用必要短时预算验证；不以省字段为由放弃身份或真实数据。
- Tracker报告合计可能重复计数，保留现有策略并明确说明，不能承诺精确去重或以兼容为名改成max。
- 已完成字节含待校验与已跳过文件数据，可能与进度条百分比不成比例；统一说明而非人为改数对齐。
- 外部客户端可以在预检后继续修改；当前协议没有CAS/事务，回读只能发现结果不符，不能消除所有并发窗口。冲突、部分成功和未知必须留给用户可见核对，不自动覆盖恢复。
- 3.00不支持任意分组编辑的前端承诺收窄是显式限制，不通过清空Tracker或静默成功模拟支持。
